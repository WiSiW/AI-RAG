# 分块大小与重叠窗口调优方案

## 目标

在不修改生产 chunk、Milvus、Whoosh 和文档参数的前提下，用固定真实问题集比较不同分块大小和重叠窗口，输出可解释的 Recall、噪声、延迟、索引成本和答案质量权衡，并允许管理员显式保存最佳参数或重建现有文档。

## 评测数据

评测集按单个知识库维护，包含：

- 数据集：知识库、文档范围、名称、版本。
- 问题：问题文本、标准答案、问题类型、是否可回答。
- 黄金证据：原文最小充分片段、归一化片段、文档、章节、字符区间和可选页码。

问题类型为 `detail/comparison/summary/reasoning/table/code/no_answer`。可回答问题必须有标准答案和至少一条黄金证据；无答案问题不进入 Recall 分母。建议每个知识库准备 50–100 条分层问题，运行门槛为 20 条可回答问题。

黄金证据不绑定当前 `chunk_id`，因此重新分块后仍然有效。保存时服务端使用空白不敏感定位计算字符区间；导入或修改时无法定位的证据会使整次操作失败。数据集编辑后版本递增，运行保存问题和证据快照。

## 参数矩阵

默认矩阵：

- 分块大小：`256/512/1024/1536 token`。
- 重叠比例：`0/10/20/25%`。
- 实际重叠 token：`round(chunk_size × ratio / 100)`，并保证 `< chunk_size`。

矩阵最多 25 组，另外保留当前知识库参数作为基线 trial。当前分块模式、解析器、Embedding、增强、Rerank、LLM、Prompt、RRF 权重、Top-K 和语义阈值固定，实验只改变大小和重叠。

## 两阶段流程

### 1. 快速筛选

- 每篇评测文档只解析一次，所有 trial 复用解析结果。
- 每 trial 构建隔离的 L2 原文向量和 BM25，使用确定性的文档/章节前缀。
- 检索固定 `candidate_top_k=20`、`final_top_k=10`、单跳、关闭 Rerank。
- 每个问题的查询向量只生成一次，并在所有 trial 中复用。
- 统计 Recall@5、Recall@10、AllEvidenceHit、MRR@10、ContextEvidenceDensity、p50/p95 延迟、chunk 数、索引 token 和估算向量字节。
- 完成后标记 Pareto 前沿，并给出默认 Top 3 推荐；管理员人工选择最多 5 个候选进入深度验证。

### 2. 深度验证

- 对选中的 trial 构建完整 v2 多表示索引：L1 摘要、L2 original/summary/questions、L3 atomic，以及 L1/L2 BM25。
- 复用知识库固定的增强、QA、Embedding 和 Rerank 模型。
- 每候选分层选择最多 30 个可回答问题生成答案，再评估 Faithfulness 1–5 和 Completeness 1–5。
- 计算 CitedGoldChunkRatio：被引用且包含黄金证据的块数除以全部被引用块数。
- 构建增强、QA 或表示失败沿用生产降级规则；发生降级时 trial 标记 `partial`，可以查看结果但不能应用。

## 指标

### Recall@K

```text
Recall@K = 前 K 个块命中的不重复黄金证据数 / 该题黄金证据总数
```

多证据、多文档题按证据数计分，同一证据被多个块命中只计一次。无答案题不进入分母。

### AllEvidenceHit@K

前 K 个块覆盖全部黄金证据的问题比例，用于识别单证据命中但无法支持完整答案的情况。

### MRR@10

首个包含任意黄金证据的块排名倒数；无命中为 0。

### ContextEvidenceDensity@K

```text
命中的不重复黄金 token 数 / 前 K 个召回块 token 总数
```

作为块内噪声代理指标；数值越高，表示召回上下文中的有效证据更集中。

### 答案质量

LLM 评判输入标准答案、召回上下文和生成答案，只输出结构化分数。参考资料视为不可信输入，Prompt 明确要求忽略其中指令。评判失败保留检索指标，trial 标记 `partial`。

## Pareto 与推荐

同时最大化 Recall@5、Recall@10、ContextEvidenceDensity，最小化 p95 延迟和索引 token。被其他候选在所有目标上不差且至少一项更好的 trial 不进入前沿。

推荐 Top 3 仅作为辅助：先过滤 p95 不超过基线 1.5 倍、索引 token 不超过基线 2 倍的候选，再按 Recall@5、Recall@10、证据密度、索引成本和延迟排序。系统不生成掩盖权衡的单一总分。

## 隔离与失败处理

- 每个 trial 使用 `eval-<uuid>` 命名空间，Milvus collection 和 Whoosh 目录均与生产隔离。
- trial 成功、失败或取消后在 `finally` 清理临时索引；删除运行和应用前也会检查并清理残留。
- 单个 trial 失败不阻塞其他 trial，运行记录原始错误。
- 同一知识库同一时间只允许一个 `queued/running` 调优任务。
- 运行删除只清理评测数据和临时索引，不触碰生产文档。
- 深度验证前重新计算源文档快照；快速筛选后源文件发生变化时拒绝继续。

## 应用与重建

- 应用只写回 `settings.chunk_mode/chunk_size/chunk_overlap` 和 `settings.last_chunk_tuning`。
- 仅深度验证中状态为 `completed` 的 trial 可以应用。
- 保存默认参数不自动重分块现有文档。
- 页面提供显式“重建现有文档”操作，批量更新评测集内文档参数并复用现有入库任务；处理中的文档跳过，接口返回排队和跳过数量。

## 数据表与 API

新增表：

- `retrieval_evaluation_datasets`
- `retrieval_evaluation_cases`
- `retrieval_evaluation_evidence`
- `chunk_tuning_runs`
- `chunk_tuning_trials`
- `chunk_tuning_case_results`

运行历史长期保留配置、指标和 Top 10 命中快照；不保留临时向量索引。JSONL 导入采用 `schema_version=1`，先完整校验再事务提交，避免部分导入。

接口、请求字段和页面行为详见 `docs/api.md`。

## 测试与验收

- 矩阵展开、重叠换算、非法比例和最多 25 组限制。
- 空白归一化证据定位、多文档/多证据 Recall、重复命中去重、MRR、证据密度和 bootstrap 区间。
- 每个问题只 Embedding 一次并在 trial 间复用。
- 隔离命名空间创建与清理，生产索引和 DocumentChunk 不变。
- 数据集版本冻结、JSONL 原子导入、运行并发限制、partial 状态和 apply 限制。
- 前端生产构建、页面轮询、Pareto 选择、结果钻取、保存默认参数和显式重建确认。

正式调优验收建议使用 50–100 条真实分层问题；至少 20 条可回答问题才允许启动实验。
