# 文档引用过滤与参考分离方案

## 摘要

文档解析完成后、分块之前统一识别正文与引用。正文进入既有 L1/L2/L3、增强、QA、Embedding、Milvus、BM25、Rerank 和回答上下文链路；参考文献、脚注和尾注单独保存为文档参考条目，只用于管理端预览，不参与检索或生成。

## 识别规则

- 规则优先识别文末精确标题：`参考文献`、`引用文献`、`参考资料`、`References`、`Bibliography`、`Works Cited`、`Notes`、`Endnotes` 等。
- 引用区必须位于文档后半段并形成连续尾段；存在后续附录、致谢或作者简介标题时在该处停止。
- DOCX 从 `word/footnotes.xml`、`word/endnotes.xml` 提取脚注和尾注；EPUB 提取 `epub:type` 或 `role` 为 footnote/endnote/rearnote 的语义节点；Markdown 提取 `[^id]` 定义；PDF 使用版面服务块类型，并以页底、小字号和脚注编号作为保守补充信号。
- 正文清理数字方括号、数字上标和常见作者-年份引用标记。代码块、表格、URL、Markdown 链接目标和参数数组不清理。
- 标题或引用条目证据不足时保留为正文。对文末小范围歧义窗口可调用知识库增强模型；仅接受与规则证据一致的连续后缀，模型失败、超时或非法 JSON 时记录 `degraded` 并继续入库。

## 数据与索引边界

- `Document.references_json` 保存引用条目：`label`、`text`、`source_type`、`page_start`、`page_end`、`section_path` 和 `metadata`。
- `Document.extracted_text` 保存过滤后的正文；原始上传文件保持不变。
- `metadata_json.reference_extraction` 保存提取状态、规则/模型来源、提示词版本、条目数量、行内标记清理数量、模型信息和降级原因。
- 引用条目不得生成 `DocumentChunk`、Embedding 或 BM25 文档，不得进入增强、QA、Rerank 或最终回答上下文。
- 过滤后没有正文时文档入库失败，不建立空索引；已提取引用仍保留供管理员检查。

## API 与页面

- 文档详情和内容接口返回 `reference_count`、`references`、`reference_extraction`。
- `POST /knowledge-bases/{id}/documents/reparse-references` 批量重建所有 `ready` 文档，返回 `queued`、`skipped`、`job_ids`。
- 文档预览页不再直接铺开引用内容；“引用参考”按钮打开弹窗，按参考文献、脚注、尾注显示，支持关键词搜索和分页翻页；正文预览只展示过滤后的正文。
- 知识库详情页提供显式“重建引用过滤”按钮并二次确认，不自动重建存量文档。

## 导出导入

- 导出包格式版本升级为 3，`documents.jsonl` 包含 `references_json`，manifest 计数包含引用条目。
- 导入继续兼容 v1/v2；旧包缺失引用字段时按空数组处理。
- 严格恢复与 rebuild 模式均保留引用条目，但引用仍不进入索引。

## 测试覆盖

- 四种格式的参考文献标题、脚注/尾注、连续性、页码与章节归属。
- 数字引用、作者-年份、上标和 Markdown 脚注清理，以及代码、URL、链接和参数数组不被误删。
- 明确规则提取不调用模型；歧义边界使用模型；模型失败时保守保留正文。
- 引用不生成 chunk 或索引，过滤后空正文明确失败。
- 批量重建只处理 ready 文档，API 序列化和前端生产构建通过。
